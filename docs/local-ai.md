# Локальная AI-интеграция

Реализован внутренний эксперимент Rendering по [ADR-0005](adr/0005-local-ai-integration.md). Общий application-порт `ImageGenerator` поддерживает создание и проверку задания; текущий адаптер — Nano Banana через Polza.AI. Это CLI-сценарий редактирования локального PNG, без кнопки в прототипе и без привязки к отсутствующим пока ревизиям.

## Настройка

Сначала запустить локальный стек: `./scripts/dev.sh up --build -d --wait` из корня репозитория. Зависимости и миграции устанавливаются автоматически. Настройки находятся в `apps/api/.env`; настоящий ключ задать в `apps/api/.env.local`, который исключён из Git. Пустой файл для локального ключа подготовлен; для нового clone можно скопировать `.env.local.example`.

```dotenv
AI_ENABLED=1
POLZA_API_KEY=ваш_ключ_из_личного_кабинета_Polza
```

Это ключ Polza.AI, а не Google AI Studio. Для вызова нужен доступ к модели и достаточный баланс. Не использовать `VITE_` и не отправлять ключ в frontend. Ключ в репозиторий и Docker image не добавлять. В dev Compose файл читается Symfony через bind mount; перезапуск и пересборка для изменения `.env.local` при CLI-запуске не нужны. Production этим файлом не настраивается.

| Настройка в `apps/api/.env` | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `AI_ENABLED` | `0` | Выключено до локального включения |
| `AI_PROVIDER` | `nano_banana` | Зарегистрированный адаптер |
| `POLZA_API_KEY` | пусто | Секрет только backend |
| `AI_NANO_BANANA_MODEL` | `google/gemini-nano-banana-2.1` | Модель из каталога Polza |
| `AI_HTTP_TIMEOUT_SECONDS` | `30` | Максимум одного HTTP-вызова, 1–120 секунд |
| `AI_POLZA_IMAGE_HOSTS` | `s3.polza.ai` | Разрешённые CDN-хосты, через запятую без пробелов |
| `AI_RENDER_ROOT` | `%kernel.project_dir%/var/ai-renders` | Приватные артефакты и журнал эксперимента |
| `AI_MAX_COST_KOPECKS` | `1000` | Резерв 10 ₽ на попытку и `provider.max_price.image` |
| `AI_BUDGET_KOPECKS` | `150000` | Предел резервов локального эксперимента, 1500 ₽ |

Можно явно выбрать документированную предыдущую модель `google/gemini-3.1-flash-image-preview`, если она доступна в аккаунте. Автоматического переключения модели нет. Актуальную доступность 2.1 и фактическую цену необходимо проверить первым реальным запросом: платный smoke без ключа не выполнялся.

## Генерация

Поместить собственный контрольный PNG шкафа в `apps/api/var/ai-reference.png`. Допускаются PNG до 10 МиБ и 16 мегапикселей. Использовать изображение самого изделия; технический SVG/PNG из ревизии появится на продуктовом этапе.

Из корня репозитория:

```sh
./scripts/dev.sh exec -T api \
  php bin/console app:ai:render var/ai-reference.png \
  'Матовый белый корпус, фасады под дуб, нейтральный интерьер, дневной свет' \
  --resolution=1K --output=var/ai-concept.png --wait=180
```

Результат сохраняется в `apps/api/var/ai-concept.png`. Команда также выводит JSON: статус, ключ кеша, provider/model, promptVersion, checksum, providerJobId, время и стоимость в копейках, если провайдер её сообщил. `costKopecks: null` означает отсутствие данных о цене, а не бесплатную генерацию. Рендер концептуальный: вручную проверить секции, фасады, ящики и пропорции; он не изменяет BOM/цену.

Коды завершения: `0` — готово, `1` — ошибка/отказ, `2` — задача ещё выполняется. `--wait=0` отправляет или проверяет задание один раз. Значение `--wait` ограничивает цикл опроса, а отдельный HTTP-вызов может дополнительно занять до `AI_HTTP_TIMEOUT_SECONDS`. При `pending`/`processing` повторить **тот же** запрос: будет проверен прежний provider job, без новой отправки на генерацию. Максимальный `--wait` — 600 секунд.

Готовый результат кешируется. Для повторного экспорта указать новый путь `--output`, поскольку существующий файл не перезаписывается. Ключ кеша учитывает исходный PNG, инструкции, разрешение, provider/model и версию промпта. Запросы с другими входными параметрами считаются новыми и могут оплачиваться.

## Ошибки и бюджет

До POST в `var/ai-renders/journal.json` атомарно сохраняется резерв и статус `uncertain`. Общая блокировка журнала защищает от двойной отправки несколькими CLI-процессами. Когда получен provider job ID, последующие запуски только опрашивают его. Если POST завершился таймаутом без подтверждённого ID, новый платный POST для этого запроса блокируется.

`failed`, `cancelled` и `uncertain` не освобождают резерв автоматически: отсутствие изображения не доказывает отсутствие списания. Даже успешные попытки удерживают первоначальный резерв; это консервативный локальный учёт. Фактическая стоимость выше резерва увеличивает учтённую сумму. У провайдера передаётся предел цены за изображение; дополнительные входные единицы/токены и изменение тарифов могут увеличить общий счёт. Для жёсткого денежного лимита дополнительно ограничить отдельный API-ключ в кабинете Polza.AI.

При неопределённом исходе сверить историю запросов/баланс в кабинете провайдера и журнал, прежде чем вручную разрешать новую попытку. Не удалять журнал для обхода бюджета или ошибки: удаление убирает защиту от повторной оплаты. Каталог журнала должен быть общим для всех локальных процессов эксперимента; для распределённого production нужен согласованный persistent store и Messenger.

Если изменился CDN-хост, запрос скачивания будет остановлен. Подтвердить новый хост по ответу/документации провайдера и добавить точное имя в `AI_POLZA_IMAGE_HOSTS`. Скачивание выполняется без API-ключа, HTTPS, без редиректов, с запретом частных сетей и ограничением размера. Результаты и журнал находятся вне web-root и исключены из Git. Это отдельные локальные артефакты эксперимента; стандартный backup БД/пользовательского Storage их не включает.

## Расширение и проверки

Чтобы добавить поставщика, реализовать `Rendering\Application\ImageGenerator`, зарегистрировать сервис с тегом `app.ai_image_generator` (для реализаций интерфейса он выставляется автоматически) и выбрать его `name()` через `AI_PROVIDER`. Порт оперирует PNG-байтами, ID задания и статусом; HTTP, секреты, URL и форматы поставщика остаются в Infrastructure. Не добавлять универсальные chat/LLM-интерфейсы, пока нет соответствующего сценария.

HTTP-контракт сверялся с [официальным OpenAPI Polza](https://polza.ai/api/openapi.json), [Nano Banana Media guide](https://polza.ai/docs/gaidy/nanobanano-2) и [GET Media Status](https://polza.ai/docs/api-reference/media/status). Используется общий `/api/v1/media`: `async: true`, одно изображение, PNG, Base64-референс; готовый файл берётся из `data.url`. Контракт-тесты не заменяют smoke с реальным ключом.

```sh
./scripts/dev.sh exec -T api composer quality
./scripts/dev.sh exec -T api composer test:coverage
```

Все автоматические тесты используют mock HTTP и временные каталоги, не оплачивают генерацию и не требуют настоящего API-ключа.
