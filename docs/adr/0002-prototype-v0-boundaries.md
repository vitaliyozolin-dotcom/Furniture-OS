# ADR-0002: границы compatibility-контракта prototype-v0

Дата: 28 августа 2026 года.

Статус: принято для технической миграции.

## Контекст

Текущая функция одновременно рассчитывает детали, фурнитуру, сроки, предупреждения и цену. Механический перенос всего frontend-кода в backend затруднил бы разделение ответственности, а исправление формул во время переноса нарушило бы parity.

## Решение

- Зафиксировать публичную пару `PrototypeCabinetInputV0 → PrototypeCalculationResultV0` как временный compatibility-контракт.
- Считать Calculation и Pricing отдельными логическими границами будущего Symfony-кода.
- Сохранить текущую TypeScript-функцию за `CalculationGateway` до подтверждённого PHP parity.
- Использовать JSON Schema и полные JSON fixtures как язык-независимые артефакты переноса.
- Не вводить Project, Revision, Catalog, Identity или Marketplace в этом контракте.

## Последствия

- PHP реализация обязана совпасть со всеми `prototype-v0` fixtures, даже если отдельная формула выглядит спорной.
- Изменение самой формулы откладывается до `ruleset-v1` и отдельного продуктового PR.
- После переключения UI на Symfony compatibility-контракт и fixtures сохраняются для объяснимости миграции.
