# Исследование AI-визуализации мебели

Дата проверки: 15 октября 2026 года. Статус: исследование; локальный эксперимент впоследствии разрешён владельцем по [ADR-0005](adr/0005-local-ai-integration.md). Инструкция реализации: [local-ai.md](local-ai.md). Платные запросы и сравнительная генерация не выполнялись.

## Вывод для российского запуска

С учётом оплаты в рублях первым кандидатом для пробной интеграции предлагается **Nano Banana 2.1 через Polza.AI**. Второй кандидат для сравнения — **GPT Image 2.5 Flare через тот же сервис**. Это предварительный выбор по доступности, документированным возможностям и цене, а не доказанное превосходство на мебельных изображениях.

Для гарантированного размещения обработки на собственных мощностях рассмотреть **FLUX.2 klein 4B**. Для небольшого пилота собственный GPU пока не обоснован измеренной нагрузкой. Прямой BFL API с FLUX.2 Pro остаётся техническим кандидатом, но доступность регистрации и оплаты для российского аккаунта не подтверждена.

Российский посредник и российское место обработки — разные требования. Возможность оплатить зарубежную модель рублями сама по себе не подтверждает российскую инфраструктуру выполнения или разрешение upstream-поставщика на конкретную схему предоставления доступа. До производственного запуска нужны подтверждение условий выбранного поставщика и проверка фактического API из окружения проекта.

## Цена и доступность

Цены ниже — опубликованные тарифы; стоимость хранения, повторных попыток и инфраструктуры отдельно. Диапазоны посредника нельзя считать гарантированной ценой редактирования конкретного PNG без выбора разрешения и параметров.

| Вариант | Опубликованная цена | Использование из России | Применимость |
| --- | --- | --- | --- |
| Nano Banana 2.1 через Polza.AI | 3–6,75 ₽ за изображение | Сервис предлагает оплату картой, СБП и расчётным счётом; рабочий запрос ещё не проверен | Первый кандидат для редактирования по референсу |
| GPT Image 2.5 Flare через Polza.AI | 4–11 ₽ за изображение | Та же схема оплаты через посредника | Второй кандидат для сравнения |
| Alice AI ART, Yandex AI Studio | 2,23 ₽ за запрос, включая НДС | Прямой российский облачный сервис | Концепты по тексту; в изученной инструкции не подтверждено редактирование контрольного PNG |
| FLUX.2 Pro, прямой BFL API | Редактирование от $0,045/МП | Российские регистрация и оплата не подтверждены | Кандидат при подтверждённом доступе |
| FLUX.2 klein 4B, собственный сервер | Нет тарифа API за картинку; оплачиваются GPU, эксплуатация и хранение | Можно разместить на выбранной российской инфраструктуре | Альтернатива при требовании локальной обработки |

Источники цен посредника: [Nano Banana 2.1](https://polza.ai/models/google/gemini-nano-banana-2.1), [GPT Image 2.5 Flare](https://polza.ai/models/openai/gpt-image-2.5-flare). Способы оплаты указаны на [сайте Polza.AI](https://polza.ai/). Это предложения самого сервиса, без независимой проверки оплаты.

Yandex: [тариф генерации](https://aistudio.yandex.ru/ru/docs/ai-studio/pricing), [пример Images API](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/images-generation). Актуальная модель — `aliceai-image-art-3.0`. Документированный пример принимает текст, ограниченный 500 символами, и возвращает Base64. Не следует обещать сохранение конструкции по PNG на основании поддержки text-to-image.

BFL: [тарификация](https://help.bfl.ai/articles/7986977817-what-are-the-costs-associated-with-using-your-models), [редактирование FLUX.2](https://docs.bfl.ai/flux_2/flux2_image_editing). Цена зависит от разрешения и входных изображений; документация отдельно описывает округление мегапикселей вверх. Значение «от» не является полной сметой произвольного редактирования.

[Карточка FLUX.2 klein 4B от разработчика](https://huggingface.co/black-forest-labs/FLUX.2-klein-4B) указывает Apache 2.0, редактирование с несколькими референсами и около 13 ГБ VRAM. Это относится к 4B: лицензию нельзя автоматически переносить на 9B или dev. Стоимость одного результата на своём GPU определяется замером времени и загрузки, а не только отсутствием платы за веса.

Другой посредник, [ProxyAPI](https://proxyapi.ru/docs/image-generation), документирует `/v1/images/edits`; [расчёты в рублях](https://proxyapi.ru/docs/balance) включают НДС. Его каталог часто показывает токены, поэтому без параметров изображения и фактического usage сопоставимую цену за рендер не фиксируем. FusionBrain и VseGPT не включены в ценовой рейтинг: получить полную актуальную официальную документацию в этой проверке не удалось.

## Прямые OpenAI и Google

Россия отсутствует в опубликованных списках [OpenAI API](https://developers.openai.com/api/docs/supported-countries) и [Gemini Developer API](https://ai.google.dev/gemini-api/docs/available-regions). Поэтому прямые подключения не предлагаются как базовая схема российского запуска. Наличие модели у посредника не меняет этот статус прямого API.

Для сравнения экономики: у Google Nano Banana 2.1 выходное изображение стоит $0,0336 для 1K, $0,0504 для 2K и $0,113 для 4K; входные данные и текст/thinking оплачиваются дополнительно. Это [Standard-тариф Google](https://ai.google.dev/gemini-api/docs/pricing), а не цена российского посредника.

Актуальная линейка OpenAI включает [GPT Image 2.5 Sunburst](https://developers.openai.com/api/docs/models/gpt-image-2.5-sunburst). Стандартные ставки: $8 за миллион входных image-токенов и $30 за миллион выходных image-токенов; текстовый вход отдельно. Фиксированную цену изображения без размера, качества и usage не выводим. Возможности редактирования описаны в [руководстве OpenAI](https://developers.openai.com/api/docs/guides/image-generation). Sunburst может участвовать в дополнительном сравнении при подтверждённом доступе; опубликованный выше рублёвый диапазон относится именно к Flare.

## Экономика пилота

При опубликованных диапазонах 1 000 изображений через Polza.AI составят 3 000–6 750 ₽ для Nano Banana 2.1 или 4 000–11 000 ₽ для Flare. У Yandex 1 000 запросов — 2 230 ₽, но это другой, текстовый сценарий. Расчёты не включают повторные попытки и не означают 1 000 принятых мебельных рендеров.

Основная метрика — стоимость принятого изображения: суммарные списания за все попытки / число результатов, прошедших проверку конструкции. Например, при 50% пригодных результатов расходы на принятый рендер примерно удваиваются. Начальный предлагаемый лимит эксперимента — 1 500 ₽, без автоматического пополнения; деньги пока не потрачены.

## Как проверить пригодность для мебели

Использовать 10 контрольных конфигураций: асимметричные секции, разное число фасадов, ящики, открытые полки, зеркало, древесная текстура и однотонные материалы. Для каждой — три задачи: смена материала, размещение в интерьере, изменение освещения. По две попытки на модель: 60 запросов на модель, 120 на два первых кандидата.

Сначала сделать по одному smoke-запросу через выбранный API из окружения проекта, сверить списание и доступные параметры. Далее сохранять исходный PNG, checksum, идентификатор модели, версию промпта, параметры, результат, длительность и фактический расход. Не включать поиск внешних изображений без необходимости.

Любое изменение числа секций, фасадов или ящиков — брак результата. Слепая ручная оценка дополнительно сравнивает пропорции, материалы и реализм. Предлагаемый порог для продолжения: не менее 90% результатов сохраняют конструкцию; каждый показываемый пользователю результат всё равно проходит проверку. Фиксировать p95 времени и стоимость принятого изображения. Числа являются предложением критериев, не результатом проведённого теста.

Ни одна выбранная модель не считается инженерным источником. Размеры, BOM и цена остаются результатом backend-расчёта.

## Предложение интеграции в этот репозиторий

Сейчас `CabinetPreview.tsx` показывает CSS-прототип. Полноценного технического SVG из ревизии, истории ревизий и пользовательского сценария Rendering ещё нет. Поэтому один подключённый API-ключ не создаст надёжную визуализацию конфигуратора.

После решения владельца первый ограниченный срез: внутренний PHP CLI-эксперимент с контрольными PNG, одним HTTP-адаптером выбранного сервиса и отчётом по цене/результату. Не добавлять публичный платный endpoint без доступа и лимитов. Этот срез проверяет модель и контракт провайдера; он не заменяет продуктовую интеграцию с ревизиями.

Целевая продуктовая цепочка уже определена в [плане проекта](project-plan.md#7-визуализация-и-ai): конфигурация/ревизия → технический SVG → контрольный PNG → AI image edit → концептуальный результат. В модуле Rendering:

- Application-порт генерации и infrastructure-адаптер Symfony HttpClient; ключи только на сервере, без привязки Domain к SDK или URL.
- Messenger job с Doctrine transport и worker в существующем Symfony backend; отдельный backend, Redis и RabbitMQ для эксперимента не требуются.
- Provider, model, promptVersion, checksum, status, стоимость, время и retry count; кеш одинаковых запросов и лимит расходов до отправки.
- Исходники и результаты через существующий FileStorage-порт; пользователь получает доступ только к своим результатам.
- Таймаут после принятия платной задачи не вызывает слепую повторную генерацию: сохраняется provider job ID, если API его предоставляет, либо неопределённый исход до сверки.
- Contract-тесты адаптера без оплаты, application-тесты лимитов/кеша/ошибок, тесты сохранности расчёта и доступа; затем opt-in smoke с реальным провайдером.

## Решение по roadmap

[План миграции, §0](technology-migration-plan.md#0-граница-плана) запрещает добавлять AI до отдельной приёмки миграции. [Продуктовый план, §13](product-development-plan.md#13-этап-10--ai-эксперимент-только-после-mvp-2) разрешает AI только после MVP-2. Приёмка миграции остаётся незавершённой согласно [ADR-0004](adr/0004-migration-acceptance.md).

Исключение, согласованное владельцем 15 октября 2026 года ([ADR-0005](adr/0005-local-ai-integration.md)): разрешить досрочный внутренний эксперимент Rendering с Nano Banana 2.1 через Polza.AI и сменяемым provider adapter, без объявления миграции принятой и без переноса остальных функций marketplace. Планы и ADR обновлены до реализации локального среза. Развёртывание собственного GPU требует отдельного решения по инфраструктуре и стеку.
